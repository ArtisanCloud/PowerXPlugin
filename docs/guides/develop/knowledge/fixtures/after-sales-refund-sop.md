# 售后退款操作手册

## 文档用途

本文档用于验证 PowerXPlugin framework knowledge provider、PowerX 底座知识空间和插件知识库调试页的基础检索链路。

推荐测试配置：

- 知识库类型：SOP / 制度 / 产品说明
- 检索策略：层次索引
- 可见范围：按当前测试租户或当前开发环境配置

## 1. 适用范围

本流程适用于普通商品订单的售后退款处理。客户在订单支付后，如商品仍符合平台售后规则，可以提交退款申请。

定制商品、虚拟商品、已经明确标记为不支持七天无理由的商品，不适用普通无理由退款流程。此类订单需要客服根据商品规则、订单备注和商家承诺单独判断。

## 2. 退款条件

客户在支付后 7 天内可以申请退款。未发货订单可以直接进入退款审核。

已经发货的订单，需要客户先提交退货申请，并在商品退回仓库完成入库确认后，才能继续执行退款。

如果订单存在优惠券、积分、组合购、赠品或部分退款，客服需要先核对订单结算明细，避免重复退款或金额计算错误。

## 3. 审核流程

客服收到退款申请后，需要检查订单状态、支付状态、发货状态、商品类型和售后历史。

符合普通退款条件的申请，由客服提交财务审核。财务审核通过后，系统进入退款执行阶段。

不符合普通退款条件的申请，客服需要在工单中说明原因，并给出可执行的替代方案，例如补发、维修、换货或升级人工复核。

## 4. 退款时效

审核通过后，退款会在 3 个工作日内原路返回。不同支付渠道的到账时间可能存在差异。

如果超过 3 个工作日仍未到账，客服需要检查退款流水号、支付渠道状态和银行处理状态，并将异常记录到售后工单。

## 5. 客服沟通规范

客服回复客户时，需要说明当前订单所处阶段、下一步需要客户完成的动作和预计处理时间。

对于已经发货的订单，客服不能直接承诺立即退款，应明确说明需要等待退货入库确认。

对于定制商品，客服需要解释定制商品不适用普通无理由退款规则，并根据订单承诺和平台规则判断是否可以进入人工复核。

## 6. 风险与例外

如果客户存在频繁退款、异常批量下单、疑似套利或恶意拒收行为，客服需要将工单标记为风险复核。

风险复核期间，客服可以继续沟通订单事实，但不能绕过审核流程直接承诺退款。

平台运营或法务介入后，最终处理意见应记录在工单备注中，作为后续检索和审计依据。
