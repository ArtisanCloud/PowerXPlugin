# 离线产物与隔离安装边界

核对日期：2026-11-09。本页与[统一发布方案](../../marketplace/plugin-developer-publishing-center-plan.md)及[实现设计](../../marketplace/plugin-publisher-implementation.md)使用相同包、授权和恢复语义。

## 1 适用场景

离线构建指工具链、依赖及配置已经在本地就绪时生成安装产物，不要求连接市场。网络隔离环境中的文件转移和宿主安装是另一项操作，不等于发布到市场或取得公开上架资格。

M1 保留本地构建和产物导出能力；市场不可用时可保存产物，恢复连接后核对再上传。当前没有承诺自动离线审核、离线 SLA、来源已验证或专用离线渠道。

## 2 当前可用的构建入口

在生成插件根目录，或 Framework 仓库转发到 skeleton 的命令入口，按执行器实际支持的平台构建：

```bash
make dist VERSION=1.2.0 PLATFORM=linux TARGET_ARCH=amd64
```

该示例的完整 Linux 运行时需在合适的 Linux 执行器校验。依赖未缓存或缺少工具链时仍会失败；“仅构建不需要市场”不代表可以无依赖完成编译。

需要现有 ZIP 产物时执行：

```bash
make package VERSION=1.2.0 PLATFORM=linux TARGET_ARCH=amd64
```

`make package` 会重新执行 dist。F03 新发布引擎已对冻结 staging 压缩一次，并提供同文件摘要复核；首个配置限原生 Linux/amd64、无 CGO Go 后端及纯 JS 前端，真实 Linux/Nuxt 运行未验收。重试复用最终选定文件。

## 3 包内容与完整性

核对唯一正式 `id` manifest、版本、显式 target、plugin.d、被引用的契约/资源、后端与迁移程序、前端运行时。摘要按最终压缩文件计算；接收方重新计算并比对文件大小和 SHA256。

排除 `.env`、市场凭据、数据库、上传文件、源码元数据和本地工具会话。路径、链接、重复条目、解压预算和执行权限须符合安装方规则。`.pxp` 后缀、signature.json 占位或 hashes.txt 不证明已有有效签名。

Go `px-plugin dist` 当前只输出 experimental 提示；旧 TypeScript 离线示例不能作为生产签名、真实分发或市场审核证据。本页不提供尚未实现的离线命令作为操作步骤。

## 4 转移和安装

使用用户选定的文件转移方式传送最终包及非敏感校验信息，再按[本地安装指南](local-install.md)执行宿主安装。安装、迁移、启用与回滚有各自授权和验收边界，不由生成 ZIP 自动触发。

接收文件成功、宿主安装成功及进程启用成功分别验证，不能只凭目录存在或传输完成判定运行正常。Core 安装行为以实际宿主版本及正式安装契约为准。

## 5 恢复后上传市场

市场恢复后显式选择原产物，核对版本和平台；新机器协议使用独立发布凭据、原 operation UUID 及同一业务内容。存在结果不明的写请求时先查询操作及市场版本。

“断网恢复”是任务和结果恢复，必要时整包重传；M1 不支持分片或字节级断点续传。公开市场仅在显式上架后可见，不能用离线产物或旧本地发布回执绕过市场身份、审核和上架流程。
