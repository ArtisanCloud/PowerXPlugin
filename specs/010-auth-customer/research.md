# Phase 0 Research — Customer Auth Modes

| Decision | Rationale | Alternatives Considered |
| --- | --- | --- |
| Adopt a `CustomerAuthenticator` interface with `local` and `delegate` implementations selected via config factory | Keeps transport/middleware agnostic of mode, allows consistent context injection, and honors Constitution’s “service-centric” rule by keeping logic inside services | Hard-code branching inside middleware (would violate separation of concerns and complicate testing); maintain two separate routers (would fragment `/mini-app` surface and duplicate logic) |
| Use JWT tokens carrying `tenant_uuid` + `customer_uuid` with existing Go JWT helpers; enforce bcrypt hashing for Skeleton credentials | Aligns with spec success criteria (token under 10 seconds issuance), reuses hardened middleware, and satisfies Zero Trust requirement; bcrypt already available in repo and easy to audit | Argon2 (more secure but not yet part of toolchain, longer implementation); opaque tokens backed by DB (adds storage lookups per request, conflicts with p95 < 500ms goal) |
| Delegate mode validation via configurable HTTP client with optional short-lived cache (TTL <= token exp) | Allows staging/prod parity, supports failure isolation, and keeps plugin stateless while meeting host-contract expectations | Embedding host SDK (none available for plugins); persisting host customer mirrors (forbidden per spec & adds data-governance risk); skipping caching entirely (okay but would amplify host latency, so cache remains optional) |
| Represent customer runtime identity as `CustomerContext` stored in Gin + request context | Provides consistent retrieval path for services, eases automated testing, and avoids re-reading headers (per FR-008) | Passing structs via handler parameters (requires invasive signature changes); using global stores (breaks concurrent request safety) |
| Expose `/mini-app/auth/register` + `/mini-app/auth/login` only when `customerAuth.mode=local` | Prevents Skeleton-only endpoints from appearing in hosted deployments, reduces attack surface, respects plan’s “Skeleton data only exists locally” statement | Always expose endpoints but guard at runtime (invites misconfiguration); never expose them (would block standalone testing) |
