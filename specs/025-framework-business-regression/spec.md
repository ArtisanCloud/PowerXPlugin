# Feature Specification: 插件业务场景回归工作台

**Feature Branch**: `025-framework-business-regression`
**Created**: 2026-10-13
**Status**: 本地实现已落地，真实 Core 授权验收待专用环境
**Input**: 为插件开发者提供可发起执行、查看步骤与业务断言、查询历史的回归工作台，并制定可供其他插件统一接入的规范；支持受控业务回归与真实平台集成回归。
**Source Plan**: [025-framework-business-regression.md](../../docs/plan/025-framework-business-regression.md)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在插件管理端执行业务场景 (Priority: P1)

作为插件开发者，我希望按业务功能查看回归场景，选择一个或多个场景执行，并看到每一步的业务预期、实际结果和依据，以判断业务行为是否发生回归。

**Why this priority**: 页面执行和业务断言构成最小可用闭环，直接满足日常调试需求。

**Independent Test**: 在已启用的专用测试环境注册一个模板生命周期场景，从管理端执行创建、修改、读取、清理，验证全部步骤和断言可见，再制造一次业务断言失败并定位原因。

**Acceptance Scenarios**:

1. **Given** 开发者具备查看和执行权限，**When** 打开目录，**Then** 能按功能、标签和回归类型筛选，并查看场景说明、依赖、验证边界及最近结果。
2. **Given** 已选择场景和测试环境配置，**When** 发起执行，**Then** 创建独立批次，逐步展示准备、操作、断言和清理的状态及耗时。
3. **Given** 某断言预期订单已支付而读回仍为待支付，**When** 场景结束，**Then** 显示失败断言的预期值、实际值和证据来源，即使业务任务本身已经结束也不能判为通过。
4. **Given** 一个场景验证重复事件行为，**When** 使用相同业务事件再次输入，**Then** 必须读取业务事实和副作用数量，验证幂等预期。
5. **Given** 场景未声明任何必要业务断言，**When** 注册场景，**Then** 明确拒绝；不能仅凭业务操作和清理成功形成通过结论。
6. **Given** 场景已声明必要断言，**When** 操作正常结束但漏报其中一项，**Then** 判为失败并列出缺失项；只产生可选断言也不能通过。

---

### User Story 2 - 恢复执行视图并处理异常与清理 (Priority: P1)

作为插件开发者，我希望离开或刷新页面后仍能查看执行记录，取消耗时场景，并在失败后知道测试资源是否清理，以便持续调试和复现问题。

**Why this priority**: 历史、异常和清理决定结果可信度，也决定是否能安全重复执行业务场景。

**Independent Test**: 执行一个可等待的场景，刷新页面、恢复记录、取消执行，再人为制造清理失败并重试清理；确认过程和原始结论保留。

**Acceptance Scenarios**:

1. **Given** 某批次仍在执行，**When** 页面刷新或重新打开，**Then** 能恢复已保存步骤并继续查看新结果；关闭页面本身不取消执行。
2. **Given** 结果更新连接中断，**When** 开发者重新连接，**Then** 补齐遗漏记录；异常明确可见，不通过隐藏的替代机制掩盖。
3. **Given** 场景正在运行，**When** 开发者取消，**Then** 停止后续操作，等待已发起操作停止，再尝试清理；不得承诺已有业务副作用被自动撤销。
4. **Given** 清理失败，**When** 查看详情或重新清理，**Then** 显示本次登记的剩余资源及新清理记录，原始测试结论不被覆盖。
5. **Given** 执行进程中断，**When** 恢复运行，**Then** 原批次标记中断，保留证据和资源清单，不自动重放业务操作。

---

### User Story 3 - 区分受控回归与真实集成结果 (Priority: P2)

作为插件开发者，我希望同一工作台支持受控回归和真实平台集成，并明确实际使用哪些依赖，以免将模拟结果当作真实授权或外部服务验收。

**Why this priority**: 两类回归分别服务日常稳定验证和真实环境验收，需要共享规范但保留证据边界。

**Independent Test**: 分别执行受控模板场景和真实平台标签绑定场景；撤销或缺失集成授权时，真实场景必须显示阻塞原因，受控场景的结果不能替代它。

**Acceptance Scenarios**:

1. **Given** 场景支持受控回归，**When** 执行，**Then** 被测业务逻辑与存储真实运行，报告逐项标明外部依赖中的测试替身。
2. **Given** 场景支持真实集成且依赖就绪，**When** 执行，**Then** 通过正式处理链路产生并读回业务事实，保留实际请求、授权边界及关联证据。
3. **Given** 必要授权或外部测试环境不可用，**When** 执行真实场景，**Then** 明确标记阻塞，不切换到受控依赖，不计为通过。
4. **Given** 两类测试配置均可用，**When** 选择其中一种执行，**Then** 不改变插件正常业务使用的全局配置。

---

### User Story 4 - 其他插件按规范接入并自动执行 (Priority: P2)

作为其他插件的开发者，我希望按统一规范维护自己的业务场景，通过参考项目接入页面和命令行，避免重复实现工作台和报告机制。

**Why this priority**: 统一接入是公共机制的交付目标，命令行与自动化执行保证场景可以持续回归。

**Independent Test**: 在参考骨架与新生成的插件项目分别注册业务场景，从页面和命令行执行，核对步骤、断言与标准报告一致。

**Acceptance Scenarios**:

1. **Given** 新插件已接入公共机制，**When** 注册场景的准备、操作、断言和清理逻辑，**Then** 场景自动进入统一目录，无需复制执行器。
2. **Given** 同一场景分别由页面和命令行执行，**When** 导出报告，**Then** 使用相同结构、证据边界和判定规则。
3. **Given** 已有失败批次，**When** 重跑失败场景，**Then** 创建关联的新批次，保留旧批次及其版本快照。
4. **Given** 自动化环境未配置真实集成凭据，**When** 请求真实集成，**Then** 报告明确显示阻塞并以非成功结果结束。

### Edge Cases

- 没有选择场景、场景标识未知、输入不符合场景声明或配置不受支持：拒绝创建，并明确原因。
- 同一提交因网络重试被重复发送：返回原执行记录，不重复产生业务副作用；用户主动重跑创建新记录。
- 已有活动执行：明确提示忙碌，首期不并行运行场景。
- 准备仅完成一部分即失败：仍清理已登记资源；异常或超时不能把场景判为通过。
- 正式业务入口返回预期的拒绝结果：按已声明的错误码和业务断言判断，不把所有非成功操作都当作测试失败。
- 异步业务未在时限内产生必要证据：显示未满足的预期，不能仅凭任务状态判断成功。
- 凭据失效或身份、租户发生变化：停止原订阅并重新验证，不能读取其他租户记录。
- 缺少必要对象 UUID：明确失败，不以其他标识兼容替代。
- 所有必要场景阻塞、跳过或中断：整批不能显示通过。
- 必要断言没有声明、重复声明、运行时漏报、被降为可选或没有必要证据：明确拒绝或给出非通过结果，不允许空断言通过。
- 执行事件缺少必要关联元信息或与批次租户不一致：拒绝保存与推送，不能以其他字段猜测补齐。
- 历史定义已变化：展示执行时的快照；重跑使用当前定义，并记录新旧版本。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须按套件和业务场景组织目录，提供功能、标签、回归类型筛选及最近结果。
- **FR-002**: 场景必须声明稳定标识、名称与说明、非空步骤、至少一个必要业务断言、输入要求、验证边界、依赖及操作和清理时限；必要断言标识在场景内唯一。
- **FR-003**: 开发者必须能在插件自己的管理端执行单条或批量场景。
- **FR-004**: 每次执行必须创建独立记录，保存场景、输入、版本、操作者和环境配置快照。
- **FR-005**: 同一提交重试必须避免重复执行；主动重跑必须创建新批次。
- **FR-006**: 系统必须显示准备、操作、断言、清理的过程、时间和结果。
- **FR-007**: 断言必须保存结构化预期值、实际值、证据来源及业务关联信息，禁止以文本日志推测替代业务断言。
- **FR-008**: 场景必须经声明的正式业务入口执行，结果明确指出验证边界；服务层结果不能替代入口与身份校验结果。
- **FR-009**: 系统必须区分执行状态和测试结论，逐项核对执行时冻结的必要断言声明；无必要断言、漏报、重复报告、降为可选、阻塞、跳过、证据缺失或清理不满足时均不能判为通过。正常操作结束却漏报必要断言必须失败并显示缺失项。
- **FR-010**: 异步业务和幂等场景必须读取最终业务事实与副作用，并遵守场景时限。
- **FR-011**: 系统必须支持受控回归与真实集成，逐项记录依赖实际采用的方式。
- **FR-012**: 回归配置必须独立绑定，不能修改正常业务配置；缺少依赖或授权必须明确阻塞，禁止隐式替代。
- **FR-013**: 每次执行必须准备独立测试数据，登记创建的资源，只清理本次拥有的资源。
- **FR-014**: 成功、失败和取消都必须尝试清理；清理失败必须显示剩余资源并支持重试。
- **FR-015**: 系统必须支持协作式取消，关闭页面不能取消后台执行。
- **FR-016**: 中断记录必须保留证据和资源，不自动重放未完成业务操作。
- **FR-017**: 系统必须保存历史并支持刷新后恢复、更新连接补读及报告导出；每条执行事件保留完整的租户、请求、追踪、来源、发生时间和版本元信息，缺失或不一致时拒绝保存和推送，补读不得改写原事件元信息。
- **FR-018**: 查看、执行和管理必须分别受权限控制；租户、操作者来自已验证身份，所有记录与更新订阅按租户隔离。
- **FR-019**: 仅在显式启用的开发或专用测试环境开放；首期同一实例只允许一个活动执行或清理作业。
- **FR-020**: 系统必须提供统一场景接入规范、参考项目及命令行执行方式，其他插件仅补充自己的业务场景。
- **FR-021**: 页面、命令行及自动化执行必须遵循相同报告契约和判定规则。
- **FR-022**: 所有业务对象及跨边界引用必须使用 UUID；界面优先显示业务名称，不能以 UUID 代替名称。
- **FR-023**: 用户可见说明、状态、错误及测试依赖的文案必须可本地化；凭据不得进入报告，其他证据必须按声明脱敏。
- **FR-024**: 必须验证本功能的关键机制、租户隔离、迁移、页面行为与生成项目接入；受控、真实授权和端到端证据分开记录。
- **FR-025**: 管理页面必须按用户任务组织为回归用例与执行记录；首屏显示可运行数量、业务验证目的和清晰的行内操作。一个场景为一个用例，内部步骤单独计数；批量操作仅在勾选后显示。
- **FR-026**: 查看用例说明应展示目的、步骤、通过条件和数据影响；运行准备通过预填业务表单完成，点击开始才创建执行，返回准备不产生业务操作。插件必须提供完整的业务展示和字段映射，缺失时明确阻止执行，不回退 JSON 输入。
- **FR-027**: 接受执行后进入当次结果详情，默认显示批次概览与各用例结论；内部按结果概览、业务校验、测试数据与清理、执行与诊断分区，桌面采用左侧纵向导航，窄屏可滚动导航。切换分区和同批次实时更新保留当前用例；失败位置、清理失败及连接异常持续可见。
- **FR-028**: 插件显式声明断言结果的业务字段与 locale，Framework 通用渲染通过及失败项的预期与实际，较大结果按需展开完整对比。资源保存业务名称、角色和同场景显式来源；清理成功必须有逐项正式读回证据与时间。缺映射、缺字段或缺历史证据明确显示，不从名称猜来源，不用 UUID 替代名称，不以 JSON 作为业务展示兜底。

### Key Entities *(include if feature involves data)*

- **测试套件**：按业务功能组织的场景集合，包含稳定 UUID 和本地化名称。
- **业务场景**：版本化的业务目标、步骤、输入声明、依赖和清理逻辑；其定义由代码注册并在执行时冻结。
- **测试配置**：启动时绑定的测试依赖集合，带稳定 UUID、可读名称和回归类型。
- **执行批次**：一次选定场景的执行，关联租户、操作者、配置、版本快照、状态和结论。
- **场景结果**：一次场景执行的步骤、断言、预期与实际值、证据及清理信息。
- **执行事件**：已持久化的执行变化，用于过程恢复、补读和审计。
- **测试资源清单**：登记本次创建资源的 UUID、归属、清理动作和清理结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首期提供至少一个受控业务场景和一个真实集成场景，均能从插件管理端发起并查看完整过程。
- **SC-002**: 100% 的必要断言可核对声明与执行结果，通过的断言必须有结构化预期、实际值和有效证据；未执行项保留原因，不伪造事实。空声明、仅可选断言、漏报、重复、阻塞、跳过、必要证据缺失七类情况均零误判通过。
- **SC-003**: 同一受控场景连续运行三次，生成三个独立批次，均达到相同业务预期并清理自己的测试资源。
- **SC-004**: 断言失败、依赖阻塞、超时、取消、中断和清理失败六类异常均能准确呈现，并保留可诊断记录。
- **SC-005**: 刷新或断线恢复后，已保存事件零丢失，原关联元信息完整且保持不变，视图与标准报告一致。
- **SC-006**: 参考骨架和一个新生成插件均按规范接入；页面与命令行报告在业务字段和判定规则上完全一致。
- **SC-007**: 两个不同租户间的记录、测试资源和更新订阅交叉访问全部被拒绝。
- **SC-008**: 未配置真实集成依赖的场景零次隐式切换为受控依赖，真实集成结果不由模拟证据替代。

## Assumptions & Scope

- 已确认：页面发起执行、两类回归均支持、场景代码与统一 SDK、工作台位于各插件管理端。
- 首期提供一种后端与一种管理端的参考实现，其他技术栈遵循公共契约，后续增加适配。
- 纯函数测试、浏览器业务场景执行器、多插件集中开发应用和外部平台内部实现不属于本期。
- 使用专用测试租户及隔离数据；真实集成凭据和能力授权由环境操作者准备，工作台不自行授予权限。
- 标准资源清理和报告保留是默认行为；不增加自动删除历史、失败数据静默保留或旧协议兼容机制。


## 用户确认的 Template 用例扩展（2026-10-15）

- controlled 目录提供 8 条独立业务用例：创建与修改、名称／说明搜索、列表分页、删除后不可访问、批量复制与副本独立、复制部分失败、HTTP 非法输入拒绝与无数据污染、内容校验与修复。每条用例独立输入、准备、事实校验、证据及资源清理；内部步骤不另计用例。
- HTTP 场景使用现有路由、DTO 和 Handler，可信身份由 Runner 注入；明确为进程内 HTTP 校验边界，不代表网络、登录、宿主授权验收。内容校验草稿由 Service 准备，不能用其创建行为替代 HTTP 的输入校验。
- 预期拒绝／部分失败被正确处理时用例应通过。对象 UUID 只在技术证据中显示，默认失败差异使用数量、匹配事实和业务字段说明。
- 表头全选仅选择当前可见列表。批量准备保留逐条目的与数据影响，预填输入按需展开，输入错误自动展开对应表单。确认后同批运行 8 条真实场景，并分别查看结果和清理状态。
- 验收包含完整批次正序与倒序、每条独立执行、浏览器和 CLI 的真实多用例批次、两个独立生成插件；保留已有同租户和其他租户对象。T045 的真实 Core 验收边界不变。
